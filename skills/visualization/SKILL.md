# Visualization

Покажи предметный результат и помоги пользователю сделать верный вывод о том, что реально
сделано. Предпочитай интерактивное демо, если взаимодействие раскрывает поведение лучше текста.
Это instruction-based MVP: HTML собирает агент под задачу, универсального renderer и live backend нет.

После основной задачи предложи одну конкретную полезную визуализацию, если она применима:
что будет видно, какие уже сохранённые данные используются, нужен ли дополнительный прогон.
Явная просьба сделать визуализацию уже является согласием. Отказ не задерживает выдачу результата.
До согласия не создавай демо и не запускай inference/камеру/сбор данных ради него.

## Выбери recipe

- Изображение, segmentation/detection, frame replay: [image-result](recipes/image-result.md).
- Парсер, extraction, сопоставление source → fields: [extraction-trace](recipes/extraction-trace.md).
- ETL, ranking, метрики, поведение функции: [data-and-behavior](recipes/data-and-behavior.md).

Прочитай только нужный recipe и [общие проверки](references/review.md). Показывай реальные входы
и outputs текущего run. Фиксируй source/sample/run IDs, версии, единицы, преобразования и ограничения.
Сохранённый результат — recorded; replay — воспроизведение записи, а не новый inference.
Учебный mockup допустим только как явно запрошенная и подписанная иллюстрация.

Если данных не хватает, покажи доступное, явно обозначь missing и предложи отдельный прогон.
Не дополняй правдоподобными выдуманными масками, trace или метриками. Выбор controls следует
доступным данным: threshold требует scores, IoU требует GT, zoom не пересчитывает модель.

## Собери и выдай

Создай standalone HTML с встроенными небольшими выбранными artifacts и без скрытых сетевых
запросов. Для большого набора предложи ограниченную выборку; не выдавай её за полный dataset.
Покажи правило отбора, включая доступные неудачные/пограничные случаи. Сторонний HTML выводи
как inert text/DOM representation; не исполняй его scripts, handlers и внешние ресурсы.

Главный экран — предметное демо. Простая схема всей системы нужна рядом, если иначе непонятны
границы и место результата. На узком экране панели складываются вертикально; labels не перекрываются,
controls доступны с клавиатуры, значения имеют текстовые подписи, не только цвет.

Используй существующую [выдачу HTML](../understand-changes/references/delivery.md): запусти
`../understand-changes/scripts/preview.py --help` для точных аргументов и выдай только
проверенный browser_link. Не требуй искать файл в filesystem. Не публикуй приватные artifacts наружу.
При составе учебного объяснения используй understand-changes с его пятью вопросами; standalone
демо не требует quiz. Поправки пользователя собирай в копируемый текстовый блок, без TXT download.

Проверь fidelity и работу controls на широком и узком экране. Отметь passed/failed/not_run.
Если browser inspection недоступна, честно укажи непроверенную часть. Демо не меняет verdict тестов.
