# Fork Tab — исправление после реального пилота

Дата: 2026-11-06. Ghostty 1.4.0, Codex CLI 0.167.0, macOS.

Реальный пользовательский запуск обнаружил два дефекта, которые не выявил исходный
smoke с заглушками в отдельном окне.

1. После создания дополнительной вкладки исходное `window-...` стало `tab-group-...`.
   AppleScript продолжал использовать старые object specifiers, поэтому установка заголовка
   завершалась ошибкой `Can’t set window id ...`. Вкладка к этому моменту уже существовала.
2. `/opt/homebrew/bin/codex` — npm entrypoint с shebang `#!/usr/bin/env node`.
   Сокращённый PATH процесса Ghostty не находил Node. Независимое локальное воспроизведение
   с PATH `/usr/bin:/bin:/usr/sbin:/sbin` дало exit 127 и `env: node: No such file or directory`.
   Пользователь также сообщил об ошибке с env; затем закрыл неудачную вкладку.

Исправления в `skills/fork-tab/scripts/fork_tab.py` и `ghostty.applescript`:

- Создание адресуется через UUID существующего terminal. После мутации старые object specifiers
  больше не используются: новое окно/вкладка определяются повторной инвентаризацией и привязкой
  к тому же исходному terminal. Сравнение старого и нового window ID убрано.
- Заголовок и выбор вкладки выполняются отдельным обращением по UUID нового terminal.
  Их сбой становится warning и не отменяет `tab-created`.
- Неопределённый результат создания требует инспекции; автоматического повторного создания нет.
- В запускаемую команду передаётся PATH вызывающего процесса. Полное окружение не копируется;
  маркеры вложенной сессии по-прежнему убираются.

Проверки после исправления:

- Повторный smoke в отдельном Ghostty window: две реальные вкладки с заглушками Codex/Claude,
  точные argv, буквальная передача cwd с кавычкой/пробелами/`$(...)`, сохранение исходного terminal.
  Временное окно закрыто; исходная пользовательская вкладка не получила ввод.
- Проверка смены window ID на фикстурах подтверждает поиск новой вкладки рядом с source terminal;
  неоднозначный набор новых вкладок и отсутствие source terminal не принимаются за успех.
- Настоящий launcher Codex с минимальным унаследованным PATH и новым env-prefix возвращает
  `codex-cli 0.167.0`, exit 0. При sandbox-проверке был отдельный warning о PATH aliases;
  он не мешал разрешению Node и запуску CLI.
- После подтверждения отсутствия закрытой неудачной вкладки выполнен реальный fork текущего UUID.
  Команда вернула `tab-created` без warning. Пользователь подтвердил: новая вкладка показывает
  историю чата и строку ввода Codex. Это подтверждение пользователя, не автоматическая проверка UI:
  Computer Use не разрешил просмотр Ghostty.

Результат: реальный сценарий Codex fork подтверждён. Для Claude проверены общий bridge и argv
с заглушкой, реальная загрузка истории Claude пока не проверялась. Установленный CLI использует
symlink на checkout, поэтому исправления применились без переустановки.
