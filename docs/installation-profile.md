# Личный профиль Engineering Harness

Этот файл подключает installer через небольшой managed block в пользовательские инструкции.
Конкретный checkout и Python указывает этот block. Пути из SKILL.md разрешай относительно
реального канонического skill, а не текущего проекта и не каталога generated wrapper.
Для Python-команд harness используй указанный managed Python: системный python3 может быть старее 3.11.

Для инженерной задачи в проекте с `.harness/knowledge/project.json` выполняй knowledge-cycle:
свежий Scout до работы, свежий Curator после outcome. Изолируй знания проекта в его БД;
для нового проекта сначала нужна явная инициализация `harness project init --root PATH --id ID`.
Не создавай общую память всех проектов автоматически. Явные project instructions, включая
legacy profile, имеют приоритет. Сам цикл памяти не включает тестирование.

Тесты создавай по запросу пользователя через test-on-request и отдельного тестового агента;
не помещай генерацию suite в контекст разработчика. Поддерживай объявленные ограничения private backend.

Для согласованного сопровождения объяснениями используй understand-changes: настройки пользователя,
task_end по умолчанию, средняя глубина, пять вопросов без подсказок по форме вариантов, HTTP-ссылка.
Для изменения архитектуры нужна читаемая обзорная схема всей системы.

После завершения задачи, если визуализация полезна, один раз предложи конкретное интерактивное
демо через visualization. Делай его после согласия; явный запрос уже является согласием.
Если реальных результатов недостаточно, показывай доступное и missing, предлагай отдельный run.
Это advisory инструкции нативным агентам, не гарантированный hook и не собственный agent loop.
