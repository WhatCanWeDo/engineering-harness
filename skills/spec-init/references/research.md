# Выбор формата · просмотрено 2026-11-06

ML Task Spec v1 — локальный формат harness для обсуждения задачи до реализации. Это инженерный выбор для данного процесса, а не общепринятый «лучший стандарт». Тексты шаблонов не копируются; ниже источники принципов.

| Подход | Сильная сторона | Почему одного недостаточно |
|---|---|---|
| [arc42](https://arc42.org/overview/) | Контекст, ограничения, устройство, решения и риски | Архитектура системы шире отдельной задачи; ML-протокол нужно уточнять |
| [Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml) | Измеримая цель, простой baseline, надёжный pipeline, связь с продуктом | Рекомендации, а не формат проверяемой постановки |
| [ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/) | Качество данных, модели, инфраструктуры и мониторинга | Readiness rubric не описывает полностью намерение заказчика |
| [Model Cards](https://research.google/pubs/model-cards-for-model-reporting/) | Intended use, ограничения и качество по релевантным группам | Документ о модели с результатами; до эксперимента результатов ещё нет |
| [ML Metadata](https://www.tensorflow.org/tfx/guide/mlmd) | Связи inputs → executions → artifacts | Lineage не заменяет требования и решение о приёмке |
| [C4 system context](https://c4model.com/diagrams/system-context) | Обзор системы, людей и внешних зависимостей | Нужно дополнить данными, ML evaluation и открытыми решениями |

Выбран компактный RFC с фиксированными разделами и явным контрактом эксперимента. В каждом конкретном документе отличаем желаемый результат от предлагаемого способа его получить. Проверяемые требования, критерии, источники и пробелы связаны ID. JSON служит единственным источником для Markdown и HTML; подробность текста свободная. Нет обязательной зависимости от TFX, arc42 tooling или облачных сервисов.

Универсальная модель документа не должна заставлять делать ML там, где нужен SQL, инфраструктура или эвристика. Data/evaluation/reproducibility/operations остаются видимыми; неприменимость объясняется. В исследовательской задаче отрицательный результат допустим, если выдержаны согласованные протокол и бюджет.
