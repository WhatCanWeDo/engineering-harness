## Метод и проверенные свойства

Прочитаны `SKILL.md`, defaults, все три reference-файла, оба Python-скрипта и HTML-шаблон. Это независимая оценка skill относительно его автора, но содержание двух документов составлено и оценено одним агентом. Поэтому семантический self-review не считается независимым подтверждением отсутствия ошибок.

Исполнены **27 Python/структурных проверок**, результаты — [python-results.json](python-results.json), воспроизводящий код — [check.py](check.py):

- До изменения значение действительно сохраняется между вызовами без повторного loader.
- После изменения свежий hit не вызывает loader; ровно на границе TTL — вызывает; чтение не продлевает срок.
- Последовательность A, B, A, C при ёмкости 2 оставляет A и C.
- Для сохранённого None invalidate возвращает True, затем False.
- Исключение loader после удаления просроченной записи выходит наружу, ключ отсутствует.
- Срок начинается после окончания загрузки: завершение t=4 и TTL=10 дают expires_at=14.
- Неположительные параметры отклоняются; обе выдержки кода точно присутствуют в after.py.
- В HTML нет внешних src/link-ресурсов, ID уникальны, payload содержит 5×4 варианта, шаблонные маркеры заменены.
- Попытка перезаписи существующего HTML отклоняется и исходный HTML сохраняется побайтно.
- Четыре вопроса вместо пяти отклоняются без HTML.
- Текст с `<script>` и закрытием script экранируется в содержимом и JSON; `escaping.html` — отдельная тестовая фикстура, не учебный результат.

**Оба реальных JavaScript блока** выполнены Node.js в минимальном DOM-стенде: [check-dom.js](check-dom.js), [dom-results.json](dom-results.json). Проверены все **40 путей клика** (20 на документ): пять fieldset, по четыре кнопки, отсутствие предварительного выбора и обратной связи, правильный verdict, объяснение выбранного ответа, правильный ответ при ошибке, повторный выбор и ровно одна активная кнопка. Это исполняемые проверки конкретного JS, а не только чтение шаблона. DOM-стенд самописный и не заменяет браузер.

Рассказ связан с поведением, а не с перечнем файлов. Конкретные примеры дают причинную связь. Указаны риски интеграции, отсутствие синхронизации и ограничение числа записей вместо размера в байтах.

Краткая версия действительно короче: около 1279 символов сериализованных блоков против 3881 в средней (это грубая метрика вместе с ключами JSON, не число видимых символов). В ней сохранены сведения, необходимые для всех пяти вопросов. Quiz одинаковый, что помогает сравнить глубину без смены проверяемых понятий; это не пять новых независимых заданий.

Все пять вопросов имеют один правильный вариант в данных условиях; проверяются TTL boundary, LRU, invalidate(None), ошибка loader и начало TTL. Неверные ответы снабжены отдельными объяснениями. ### Найденные проблемы

1. **Medium — дефект skill/renderer: неатомарный сбой при записи истории.**
   `render_explainer.py:main` открывает и записывает output, затем создаёт каталог истории и пишет историю. Воспроизведение: `--history independent/history-parent-file/history.jsonl`, где `history-parent-file` — обычный файл. Команда возвращает exit 2, но уже создала `partial.html`. Повтор с валидным `--history independent/retry-history.jsonl` и тем же output тоже возвращает exit 2: output существует. [Доказательство](partial-write-result.json). Ошибка не повреждает исходные файлы и обычный корректный путь работает. Рекомендация: проверить возможность подготовки истории до финального создания output либо обеспечить явную транзакционность/понятную семантику частичного успеха и безопасное восстановление. До использования как надёжной автоматической операции со штатным retry это стоит исправить; для разового учебного документа с валидными путями не блокер.

2. **Low — недостаток конкретного созданного quiz: слабые дистракторы q5.**
   Варианты «В t=4: время загрузки полностью расходует срок» и «В t=20: загрузка даёт два последовательных срока» гораздо менее правдоподобны, чем ошибочный отсчёт от начала запроса t=10. Их можно отсеять по здравому смыслу без знания реализации. Это облегчает задачу и не полностью соблюдает требование skill о реалистичных заблуждениях. Генератор закономерно не обнаруживает этот семантический недостаток; его проверка ограничена структурой и эвристиками. Исходный результат оставлен неизменным для честной оценки. Перед выдачей как отобранного образцового quiz q5 следует переработать и повторно проверить смысл. Это недостаток выполнения инструкций агентом, не доказанный баг Python-генератора.

## Настройки, история и пауза

Первый вызов: `preferences.py --path independent/preferences.json show --depth medium` → `task_end/medium`.
Второй: `show --depth brief --frequency on_request` → `on_request/brief`.
Последующий `show` без overrides → снова `task_end/medium`; `preferences.json` не создан. Ничего глобально не сохранено, команда set не использовалась. Повреждённая локальная настройка `bad-preferences.json` не маскируется override и даёт exit 2.

История всегда направлялась в изолированную папку либо отключалась. Первый рендер записал одну строку; второй с тем же quiz не увеличил историю (`history_recorded:false`). История содержит хеш, позиции и длины, без текстов и результатов ответов. Реальный многодокументный исторический bias на длинной серии не проверялся.

Режим `on_request` испытывался в явном запросе оценщика создать дополнительный вариант. Режим `milestone`, длительная задача и реакция на реальное «дальше» не разыгрывались. Документ содержит требование вернуться в диалог, skill явно называет паузу договорённостью, а не механизмом блокировки. После создания основного документа работа оценщика продолжилась по исходному разрешению на сравнение и проверки; это не автоматический переход к следующему этапу пользовательской инженерной задачи. Нельзя по этому прогону утверждать, что пауза надёжно соблюдается другим агентом в длительном диалоге.

## Удобство и пределы проверки

Плюсы по разметке/коду: автономный файл, содержание со ссылками на секции, явные исходные пути, читабельные блоки кода, адаптивные CSS-правила, keyboard focus-visible, fieldset/legend, aria-pressed и live-feedback. Пути к исходникам представлены текстом, не кликабельными ссылками; это разрешено контрактом, но открытие кода вручную менее удобно. Технические ответы содержатся в исходном HTML — ожидаемое свойство учебного документа, явно заявленное skill, не защищённого экзамена.

**Не проверено:** реальный рендер в браузере, переносы и визуальный вид на desktop/mobile/print, реальный CSP/file:// режим браузеров, мышь/клавиатура/скринридер, визуальная доступность feedback, интернет-запросы реального браузера, конкурентная запись истории, статистика долгой серии quiz, работа без Python, установка и автоматическое обнаружение skill агентами, реальные пользователи и долговременное понимание. `command -v chromium` и `command -v google-chrome` ничего не вернули; браузер через другие интерфейсы не запускался. Проверка статических зависимостей и DOM-стенд подтверждают ограниченные свойства, но не заменяют эти проверки.

Скрипты теста создают уникальные выходы и демонстрируют запрет перезаписи: повторный запуск `check.py` целиком потребует новой папки или новых имён для тестовых HTML. Повторный запуск `check-dom.js` безопасен в текущей папке.
