# Fork Tab — проверка 2026-11-06

Реализованы общий Python CLI, AppleScript bridge к Ghostty, тонкие Codex/Claude skills
и идемпотентный installer пользовательских symlinks без перезаписи чужих файлов.
Runtime: Ghostty 1.4.0, Codex 0.167.0, Claude Code 2.1.224, macOS.

Проверено исполнением:

- Dry-run текущего Codex tool call получил точный UUID из CODEX_THREAD_ID и выбрал единственное окно.
- В отдельном временном окне Ghostty реально созданы две вкладки через production helper.
  Исполняемые файлы Codex/Claude подменены контролируемыми заглушками: получены точные argv
  `fork UUID --cd PATH` и `--resume UUID --fork-session`.
- Новые вкладки принадлежат явно выбранному тестовому окну; исходные window/tab/terminal IDs сохранены.
  Временное окно закрыто после проверки, исходный чат не получил ввод.
- Рабочая папка с пробелами, одинарной кавычкой и `$(...)` передана буквально. Командная подстановка не исполнилась.
- Неоднозначный выбор между окнами, неизвестное окно и некорректный UUID отклонены.
- Installer в отдельном временном home переживает повторный запуск; конфликт существующего файла
  отклоняется до установки ссылок, чужое содержимое сохранено.
- Оба SKILL.md прошли штатный quick_validate в проектном virtualenv.

Первичная проверка выявила конфликт слова `tab` в словаре AppleScript: вместо разделителя
получалась строка `tab`. Исправлено явным character id 9 и подтверждено повторным прогоном.

Границы результата: native CLI help и документация подтверждают синтаксис fork, но загрузка
реальной истории Codex/Claude в созданной вкладке этим smoke-прогоном не проверялась.
Ответ `tab-created` означает только создание вкладки; ошибки native CLI видны в ней.
Общий Codex daemon не имеет TTY исходного клиента и может хранить устаревший GHOSTTY_SURFACE_ID;
helper не доверяет этой переменной и не выбирает окно по фокусу. При нескольких окнах
без TTY нужен явный выбор пользователя.
